The cap isn't the problem. The clock is. Start at nine, run dry by 10:40, and you wait until two. Open the window at six instead and it resets at eleven, while you're still at your desk. One small message, sent before you wake up, moves your resets into your working hours.

Modes

Two modes. One quiet ping.

Pick fixed times, or let it chain windows back to back. Either way it's one bash script on your machine, using the login you already have.

Schedule

  • Catches up on wake

Mode 2 / Back to back

Watch

Checks every five minutes and opens the next window as soon as the last one resets, all week. It reads reset times from Claude's reply and Codex's own logs, so checking costs no quota.

  • No quota to check

FAQ

Questions.

Does this give me more usage?

No. Your caps stay the same. UsageForge changes when each 5-hour window starts, so a reset lands while you're working instead of while you're asleep.

How much quota does a ping use?

Very little. Claude gets one short Haiku message with tools, hooks, plugins and MCP servers turned off. Codex gets one read-only codex exec at low reasoning effort. Watch mode sends about 4–5 pings a day per tool, and each one counts a little toward your weekly cap.

Is it safe for my account?

UsageForge uses the official programs, your own login, on your own machine. It never extracts a token or shares an account, and it sends a few tiny messages a day with random timing. We found no report of anyone banned for scheduled pings. Anthropic's and OpenAI's terms leave automation a grey area, though, so read them and decide for yourself. Schedule mode is the most conservative choice.

Does my computer need to be awake?

Yes. A sleeping laptop can't send anything. On macOS, launchd runs a missed ping as soon as the Mac wakes. To wake it on a schedule, run sudo pmset repeat wakeorpoweron MTWRFSU 05:58:00.

What happens when I hit a cap?

UsageForge reads the reset time from Claude's reply or Codex's logs and waits until then. It doesn't send pings that can't succeed.

How do I remove it?

Run usageforge stop, then delete the repo and ~/.local/state/usageforge.
